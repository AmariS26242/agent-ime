## 构建与签名

- Release keystore 不进仓库，只存在于本机 `%USERPROFILE%\.android-keys\agentime-release.jks` 与 GitHub Actions Secrets（`RELEASE_KEYSTORE_BASE64` / `RELEASE_STORE_PASSWORD` / `RELEASE_KEY_ALIAS` / `RELEASE_KEY_PASSWORD`）。
- `app/build.gradle.kts` 只从环境变量读签名凭据，缺凭据时产出未签名包；CI 用 `AGENTIME_REQUIRE_SIGNING=true` 把「未签名」变成硬失败。
- 版本号可用 `-PappVersionCode` / `-PappVersionName` 覆盖，用于升级测试，无需改代码。
- 流水线：`.github/workflows/release.yml`，`assembleRelease` → apksigner 验签并断言证书指纹 → unzip 断言双 ABI 的 `librime.so`/`librime_jni.so` 与 `assets/rime`、`assets/licenses` → `aapt2 badging` → 输出 SHA-256/证书指纹 → 上传 artifact（保留 30 天）。
- 细节见 [release-signing.md](<release-signing.md>)。

CI 修复记录：首轮 run 41215779037 在验签步骤失败，原因是 `apksigner --print-certs | grep 'Signer #1 ...'` 在 `bash -eo pipefail` 下 grep 落空导致整步静默退出；改为从 apksigner 全量输出中取 `certificate SHA-256 digest` 末行（兼容 `Signer #1…` 与 `V2 Signer:…` 两种格式），并在失败时输出 `::error::` 明细，见提交 `a3ca063`。

## API 29 补测

环境：新建 AVD `AgentIme29`（`system-images;android-29;google_apis;x86_64`，Pixel 2），Android 10（API 29），1080x1920 / density 420，三键导航（`navigation_mode=0`）。安装 release APK（versionCode 2）并在首次弹出键盘前未做任何键盘交互，覆盖「首次 inset」场景。

- 首次弹出：`dumpsys window` 显示 IME 窗口 `mFrame=[0,1077][1080,1920]`（铺到底，导航栏覆盖其上），键盘内容实际绘制到 y=1793，导航栏 `1794..1920`（126px）→ 底部行完整露出，未被导航栏裁切。
- 对比量测（`measure_inset.py`）：键盘最底内容行 y=1793、导航栏顶 y=1794，间隙 1px；九键态底行 y=1621..1764，与导航栏留 30px。
- 隐藏 / 再显示后复测：同样 1793/1794，未见 padding 累积或首帧漏 padding。
- 功能复测：中文输入 `nihao → 你好` 正常（`RimeEngine: pinyin 'nihao' -> 9 candidates, first=你好`）；九键 `64426` → 12 个分词、首选「ni hao」，候选栏出现且底行 `26键/0/回车/退格` 完整。
- 截图：`42-api29-first-show.png`（首次弹出）、`43-api29-committed.png`、`44-api29-ninekey.png`、`45-api29-ninekey-cands.png`、`46-api29-reshow.png`。

结论：代码中 `initialNavBottom` 在 API < 30 取 0，依赖 `ViewCompat.setOnApplyWindowInsetsListener` 在布局后补 padding；实测首次弹出虽走的是「inset 到达后」路径，但键盘内容已在首帧对齐到导航栏上沿，**未复现交接摘要里担心的底部行被遮挡问题**。

## 已知问题与风险

1. `TYPE_TEXT_FLAG_NO_SUGGESTIONS` 的普通输入域会被判为敏感，强制直输且不显示候选。实测：系统设置搜索框、Wi-Fi SSID 输入框。密码/验证码等真敏感域是期望行为，但搜索框/SSID 属于误伤，需评估是否细化判定（`AgentImeService.kt:237-245`、`:362-363`）。
2. Agent 草稿输入拼音时，草稿框只显示提示文案，不显示正在组合的拼音串（只有候选栏可见），用户无法确认已敲的字母。
3. 敏感态下点「九键」无任何提示，键盘保持直输（不切换布局）。
4. 真机（arm64 实机）安装与升级尚未验证，只验证了 x86_64 模拟器双 ABI 包内容。
5. GitHub Actions 仍有 Node.js 20 弃用告警，不影响当前构建。
