# 中文输入引擎选型与九键方向

## 决策

后续成熟中文输入引擎选用 **Rime/librime**，目标是通过 Android NDK 嵌入当前 `InputMethodService`，再用 Rime schema 定义全拼、九键和后续其他方案。

选择理由：

- librime 官方仓库声明核心使用 3-Clause BSD，允许作为应用的一部分集成，但发布时仍需附带版权和许可证文本。
- 官方文档把输入方案作为可配置的 YAML schema，适合把九键映射与 Agent 输入法自己的键盘界面分开维护。
- 官方 `rime-luna-pinyin` 提供成熟全拼方案；九键需要单独方案或自定义 schema，词库与方案文件的许可必须分别记录。

Fcitx5 Android 保留为备选和参考实现。它官方支持中文拼音、双拼、五笔和自定义表，但仓库说明它是完整 Android 输入法工程，键盘布局尚不可自由定制；其上游也把 T9 Pinyin 列为布局控制待完善事项。把它直接嵌入当前应用的工程成本和边界都更大。

## 当前交付

- 普通键盘工具条增加“九键/26键”切换。
- Agent 提问面板也增加“九键/26键”切换，提问、追问和改写意图共用同一套候选适配层。
- 九键采用手机式 3×3 数字布局：`2 ABC`、`3 DEF`、`4 GHI`、`5 JKL`、`6 MNO`、`7 PQRS`、`8 TUV`、`9 WXYZ`。
- 数字序列会从现有有限拼音词表生成候选；`0` 确认首候选或输入空格，底部提供回车和退格。
- 该实现是交互 POC，仍不满足全量中文输入验收。
- `ChineseInputEngine` 已成为 UI 与引擎之间的接口，默认实现已切换为 `RimeChineseInputEngine`；在缺少 `rime_jni` ABI 的开发包中才回退到 `LimitedChineseInputEngine`。接入真正的 librime 构建产物时无需改动键盘 UI 和候选交互。

## 下一步接入顺序

1. 引入 librime 的 Android native 构建链和 ABI 产物。
2. 加入经过许可证核查的拼音方案、词库和第三方许可证清单。
3. 把九键数字序列转换成 Rime preedit，使用 Rime 候选结果替换当前有限词表适配器。
4. 在真实设备上回归 26 键、九键、候选选择、退格、回车、密码输入和输入框切换。

当前工作机没有 Android NDK、CMake 或 Gradle 可执行文件，因此本轮完成了默认引擎切换和 JNI 边界，但尚未声称 `rime_jni` native ABI 已经编译或随 APK 发布。
